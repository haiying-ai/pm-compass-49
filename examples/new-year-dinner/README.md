# 年夜饭端到端示例

这个示例把一顿家庭年夜饭当作一个可交付项目，展示 Skill 如何在不增加复杂官僚流程的前提下使用49过程框架。

## 项目任务书

- 项目：2027年家庭年夜饭
- 项目经理：爸爸
- 发起人：全家
- 范围：8道菜、12位家人、除夕19:00开饭
- 预算：1200元
- 约束：两口灶、老人低盐、小朋友不吃辣

## 推荐对话剧本

```text
新建一个“2027年家庭年夜饭”项目，负责人是爸爸，发起人是全家，预算1200元，12人参加，除夕19:00开饭。

执行4.1 制定项目章程：记录目标、约束、成功标准和假设。

执行5.2 收集需求：收集老人低盐、小朋友不吃辣、必须有鱼和饺子等需求。

执行5.4 创建WBS：拆成菜单、采购、洗切腌制、凉菜、热菜、上桌验收。

执行6.5 制定进度计划：倒排采购、备菜、烹饪和19:00开饭时间。

执行7.3 制定预算：把1200元分配到海鲜肉类、蔬菜调料、饮品水果和预备金。

执行11.2 识别风险：记录买不到鱼、灶台拥堵、过敏、延误等风险。

做G1阶段门禁评审。

更新风险台账：市场没有新鲜鱼，启动鸡肉替代方案。

生成项目周报。

完成上桌验收并关闭项目，记录经验教训。
```

## 预期结果

Skill 应创建标准项目目录，形成章程、范围基线、时间表、预算、风险登记册、门禁记录和报告。G0/G1在计划获全家确认后通过；G2在采购和备菜准备就绪后为 `ready`；G3必须等菜品验收完成后才可通过；G4记录收尾和经验教训。

## 测试要点

1. 用“识别风险”或 `11.2` 均应定位到同一个过程。
2. 缺少菜单或预算时，G1应显示 `blocked`，而不是假定已批准。
3. 把“临时增加蛋糕”作为变更请求，要求分析范围、成本、进度和质量影响。
4. 把“清点风险”作为口语输入时，Skill应请求澄清或建议使用标准过程名“识别风险”。
